# Хранилище MCP

Плагин для харнесса, добавляющий вкладку **«Хранилище MCP»** в *Настройки → Плагины*,
сразу после **«Коллекции»** скиллов. Это **реестр MCP-серверов** — что каждый из них
собой представляет, что он даёт агенту и стоит ли за ним тянуться, — и это таблица из
трёх столбцов:

| Сервер | Комментарий | Мини-описание для агента |
|---|---|---|
| короткое уникальное имя, которое становится пространством имён инструментов `mcp__<имя>__<инструмент>` | заметка оператора, свободный текст, на любом языке, на котором он пишет | одно-два предложения, **написанные для агента**: что этот сервер даёт и когда за ним тянуться |
| `vkusvill` · предложен | ВкусВилл, свой MCP. Без ключей. | Поиск товаров ВкусВилл: поиск, детали по id или штрихкоду, аналоги, скидки, магазины, рецепты и ссылка на корзину. Он НЕ заказывает и не может платить. |

Главный здесь третий столбец. Это та строка, которую будущий агент читает, решая, стоит
ли этот сервер своих токенов, поэтому запись без неё не принимается.

## Это реестр, а не конфигурация

**Этот плагин никогда не пишет MCP-конфигурацию харнесса.** Сервер загружается строкой в
патч-слое профиля, а запись в этот файл меняет то, что сможет вызвать каждая следующая
сессия, — это другое действие, с другим радиусом поражения, чем заметка о сервере.
Хранилище, которое тихо включало бы собственные записи, сделало бы каждую строку решением,
которого никто не принимал.

Вместо этого панель **показывает точные строки для вставки и точный файл, куда они идут**,
а вставляет их оператор. Сниппет считает host-половина, его возвращают инструменты, и он
показан в поле только для чтения: это текст, который переносит человек, а не запись,
которую делает этот код.

По той же причине панель умеет убрать строку и не имеет кнопки, которая её добавляет:
нажатием человек может *забыть*, а агент может *записать*.

## Куда идёт сниппет

Вот что было найдено на этой машине — как находка, а не как правило:

- `dsh-mcp-client` (`@deepseek-ai/dsh-mcp-client`) превращает внешние MCP-серверы в
  родные инструменты харнесса с именами `mcp__<serverName>__<rawName>`. В его README
  сказано, что он настраивается строкой с `serverName`, `transport` (`stdio` или
  `streamable-http`) и либо `command` + `args`, либо `url`.
- Живой патч-слой оператора — `$DSH_HOME/profiles/web/cordis.patch.yml`, и **ни одной
  строки MCP в нём сегодня нет**. Значит, из этого хранилища не загружено ничего, и каждая
  запись честно `предложена`.
- Сниппет хранилища написан именно для этого файла. `settings.yaml` тоже проверен: ключа
  `mcp` в нём нет вообще, поэтому **не** оттуда этот харнесс читает свои серверы.

Если будущая версия станет читать MCP-серверы откуда-то ещё, менять придётся ровно одно
место — сниппет, и это одна функция.

## Схема

Один файл в домашнем каталоге харнесса, `$DSH_HOME/mcp-store.json`, с той же формой
версии, что у соседнего каталога:

```json
{
  "version": 1,
  "updated": "2026-09-21T15:57:51.878Z",
  "entries": [
    {
      "id": "vkusvill",
      "name": "vkusvill",
      "transport": "streamable-http",
      "url": "https://mcp001.vkusvill.ru/mcp",
      "command": "",
      "args": [],
      "comment": "ВкусВилл, свой MCP. Без ключей.",
      "description": "Product lookup for VkusVill: search, details by id or barcode, ...",
      "status": "proposed",
      "source": "https://mcp001.vkusvill.ru/mcp",
      "addedAt": "2026-09-21T15:00:00.000Z",
      "updatedAt": "2026-09-21T15:00:00.000Z",
      "found": [{ "at": "2026-09-21", "fact": "initialize и tools/list отвечают анонимно, HTTP 200." }],
      "observations": []
    }
  ]
}
```

| поле | что это |
|---|---|
| `id` | стабильный и читаемый; выводится из имени и вместе с ним не меняется |
| `name` | короткое уникальное имя, становящееся пространством имён `mcp__<имя>__<инструмент>` |
| `transport` | `stdio` или `streamable-http` — два, которые принимает мост харнесса |
| `url` / `command` + `args` | адрес для http; исполняемый файл и его аргументы для stdio |
| `comment` | заметка оператора, хранится дословно, не переводится и не переписывается |
| `description` | **для агента**, а не для человека. Обязательно. |
| `status` | `proposed` · `tried` · `working` · `refused` |
| `source` | ссылка на то, откуда он взялся |
| `addedAt` | когда он попал в хранилище. Хранилище без дат — это куча. |
| `found` | датированные **измерения** — что ответил адрес, с этой машины |
| `observations` | датированные измерения, добавленные позже, новые сверху |

`found` и `observations` — это разница между хранилищем и списком желаний: утверждение о
том, что сервер умеет, стоит ровно столько, сколько за ним измерено, и дата говорит,
когда.

## Инструменты, которые вызывает агент

Четыре инструмента, зарегистрированные в реестре инструментов харнесса, — чтобы у фразы
«добавь это в хранилище MCP» в чате было куда лечь.

| инструмент | что делает |
|---|---|
| `mcp_store_add` | записывает один сервер. Требует `name` и `description` для агента; отказывает на транспорте, которого в харнессе нет, на http-записи без адреса и на stdio-записи без команды |
| `mcp_store_list` | все записи с описанием, состоянием, измерениями и сниппетом, который из них получится. Читать это **до** поиска сервера |
| `mcp_store_update` | меняет указанные поля и **оставляет остальные как были**; отказывает на пустой строке, а не молча очищает поле |
| `mcp_store_note` | записывает, что сервер реально ответил, с датой, добавляя к прежнему. `proposed` становится `tried`; запись `working` или `refused` сохраняет уже принятое решение |

Результат каждого инструмента проверяется по объявленной им схеме вывода, потому что
результат, который реестр отвергнет, падает уже **после** записи.

## Состояния

| состояние | смысл | цвет |
|---|---|---|
| `proposed` | записано, здесь ни разу не запускалось | нейтральный |
| `tried` | запускали, и результат ещё не вердикт | янтарный |
| `working` | измерено работающим с этой машины | зелёный |
| `refused` | решение против, с причиной в измерениях | красный |

`working` и `refused` — это решения, и новое измерение молча не отменяет ни то ни другое.
Именно поэтому автоматически двигается только `proposed`.

## Что в нём при первом запуске

Первый запуск кладёт два сервера, найденных **21.09.2026**, оба `proposed`, потому что в
этом харнессе не загружен ни один из них:

| | |
|---|---|
| **ВкусВилл** — `https://mcp001.vkusvill.ru/mcp` | Восемь инструментов: `vkusvill_products_search`, `vkusvill_product_details`, `vkusvill_product_barcode`, `vkusvill_product_analogs`, `vkusvill_products_discount`, `vkusvill_shops`, `vkusvill_recipes` и `vkusvill_cart_link_create`. Он **не** оформляет заказы и не может платить — последний шаг это ссылка на корзину, которую открывает человек. `initialize` и `tools/list` отвечают анонимно; `tools/call` на поиск товара ответил **HTTP 200** с реальными данными, но только после полного рукопожатия. Первый зонд, пропустивший уведомление `notifications/initialized`, получил **HTTP 403**, и это записано рядом с 200, чтобы поздний читатель отличил ошибку протокола от стены с ключом. |
| **draw.io** — `https://mcp.draw.io/mcp` | Официальный сервер `jgraph/drawio-mcp`. `create_diagram` рисует draw.io XML прямо в чате, а `search_shapes` находит нужную строку стиля среди 10 000+ фигур библиотек. Для встроенного показа нужен хост с расширением MCP Apps; где его нет, инструмент возвращает XML текстом. Диаграммы, отправленные на этот адрес, уходят с машины. Тот же репозиторий публикует и stdio-сервер (`npx @drawio/mcp`), открывающий диаграммы в редакторе draw.io. |

## Когда что нужно

| что меняется | что для этого нужно |
|---|---|
| запись, её состояние, измерение, сниппет | **ничего** — пишется и читается вживую |
| первая установка плагина | обновить страницу (F5) |
| обновление уже установленного | перезапустить `dsh web` |
| чтобы сервер действительно загрузился | оператор вставляет сниппет в патч-файл и перезапускает |

## Чего вкладка не делает

- **Не загружает сервер.** См. выше: она отдаёт строки для вставки.
- **Не проверяет сервер.** Зонд адреса по кнопке в браузере поставил бы сетевой вызов за
  нажатие; это делает агент и записывает результат через `mcp_store_note`.
- **Не переводит комментарий.** Твоя заметка — это твоя заметка.
